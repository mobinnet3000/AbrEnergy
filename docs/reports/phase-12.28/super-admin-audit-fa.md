# گزارش ممیزی امنیتی و اعتبارسنجی نقش: مدیر ارشد سیستم (Super Administrator)

**شناسه سیستمی نقش:** `super_admin`  
**تاریخ ارزیابی:** ۲۹ اکتبر ۲۰۲۶ (فاز ۱۲.۲۸)  
**محیط اجرا:** تست مستقل بک‌اند DRF + فرانت‌اند Next.js 15 + پایگاه‌داده ایزوله  
**نتیجه ارزیابی:** **تأیید کامل (PASS)**

---

## ۱. اهداف و مرزهای عملیاتی نقش

مدیر ارشد سیستم بالاترین سطح دسترسی فنی و اجرایی را در سامانه ابر انرژی داراست. این نقش مسئولیت مدیریت زیرساخت نرم‌افزاری، پیکربندی‌های کلی وب‌سایت، مدیریت کاربران و پایش امنیتی را بر عهده دارد.

### قابلیت‌های تست‌شده و تأییدشده:
1. **مدیریت تنظیمات کلان سایت (`/admin/settings`):**
   - ویرایش و ذخیره‌سازی نام شرکت، اطلاعات تماس، ایمیل سازمانی و آدرس پستی.
   - بارگذاری و به‌روزرسانی دارایی‌های برند (لوگو و فاوآیکون) با بررسی محدودیت حجم و پسوند.
   - تنظیم متادیتاهای پیش‌فرض سئو (عنوان، توضیحات و کلمات کلیدی پیش‌فرض).
   - اعتبارسنجی پایداری داده‌ها: داده‌های ذخیره‌شده از طریق `PATCH /api/v1/admin/site-config/` در دیتابیس ثبت شده و پس از رفرش صفحه با مقادیر واقعی بازیابی می‌شوند.
2. **مدیریت کاربران و دسترسی‌ها (`/admin/users`):**
   - ایجاد حساب کاربری جدید برای تمامی نقش‌های ۹ گانه (`POST /api/v1/admin/users/` با وضعیت ۲۰۰/۲۰۱).
   - تغییر نقش کاربران و فعال/غیرفعال‌سازی حساب‌ها.
   - اعتبارسنجی حفاظت از آخرین مدیر ارشد: ممانعت از تنزل رتبه یا غیرفعال‌سازی تنها مدیر ارشد فعال سیستم (`SoleSuperAdminGuard`).
3. **لاگ فعالیت‌ها و ممیزی رویدادها (`/admin/activity-log`):**
   - مشاهده تمامی وقایع ثبت‌شده با جزئیات آدرس IP، تغییرات فیلدها و شناسه کاربر.
4. **ماژول‌های محتوایی و کاتالوگ:**
   - دسترسی کامل (ایجاد، ویرایش، انتشار، حذف) در استودیو صفحه اصلی، مقالات، خدمات، پروژه‌ها، محصولات و دسته‌بندی‌ها.

## ۲. آزمون رفتاری API و کدهای وضعیت

| ماژول / عملیات | آدرس Endpoint | متد | وضعیت مورد انتظار | وضعیت مشاهده‌شده | نتیجه |
| :--- | :--- | :---: | :---: | :---: | :---: |
| خواندن تنظیمات سایت | `/api/v1/admin/site-config/` | GET | 200 OK | 200 OK | تأیید |
| به‌روزرسانی تنظیمات | `/api/v1/admin/site-config/` | PATCH | 200 OK | 200 OK | تأیید |
| ایجاد کاربر جدید | `/api/v1/admin/users/` | POST | 201 Created | 201 Created | تأیید |
| تنزل آخرین مدیر ارشد | `/api/v1/admin/users/{id}/` | PATCH | 400 Bad Request | 400 Bad Request | تأیید |
| مشاهده لاگ فعالیت‌ها | `/api/v1/admin/activity-log/` | GET | 200 OK | 200 OK | تأیید |
| آمار مدیریتی پیشرفته | `/api/v1/admin/dashboard/stats/` | GET | 200 OK | 200 OK | تأیید |

## ۳. حفاظت و پایداری داده‌ها

- **قفل همزمانی:** تابع `check_last_super_admin_violation` درون تراکنش اتمیک و با استفاده از `select_for_update()` روی ردیف‌های پایگاه داده اجرا می‌شود؛ لذا حتی در درخواست‌های همزمان، امکان قفل شدن سیستم به دلیل حذف تصادفی سوپرادمین وجود ندارد.
- **انعکاس بلادرنگ:** هرگونه تغییر در وضعیت کاربر (غیرفعال‌سازی یا تغییر نقش) بلافاصله در درخواست بعدی احراز هویت با JWT اعمال می‌شود.
